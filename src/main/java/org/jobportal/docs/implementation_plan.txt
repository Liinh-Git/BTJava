# IMPLEMENTATION PLAN - JOB PORTAL SYSTEM

## 1. Mục đích tài liệu

Tài liệu này mô tả cách chia việc, thứ tự triển khai và checklist bàn giao cho dự án JobPortalSystem.

Dự án chia theo folder/tầng:
- DAL/DAO
- BLL/Service
- View/Swing
- Model/DTO/Enum/Utils nền tảng

Hiện tại:
- Schema đã chốt.
- Model/DTO/Enum đã có nền.
- Service/DAO đã có prototype/skeleton.
- Java project đã compile được.
- Bước tiếp theo là implement thật DAO, BLL và View binding.

---

## 2. Nguyên tắc triển khai

1. Không làm toàn bộ app một lần.
2. Làm theo module ưu tiên.
3. Mỗi module đi qua đủ 3 tầng: DAO → Service → View.
4. View không gọi DAO.
5. DAO không xử lý nghiệp vụ.
6. Service không chứa Swing code.
7. DTO là dữ liệu View dùng để hiển thị.
8. Model bám sát database.
9. Mỗi lần xong một phần phải compile.
10. Nên commit theo từng mốc nhỏ.

---

## 3. Chia vai trò trong nhóm

## 3.1. Người làm DAL/DAO

Phụ trách:
- DatabaseConfig
- UserDAO
- CandidateDAO
- EmployerDAO
- CategoryDAO
- RecruitmentDAO
- ApplicationDAO
- CVDAO
- NotificationDAO nếu làm sau

Nhiệm vụ chính:
- Viết SQL đúng schema.sql.
- Mapping ResultSet sang Model/DTO.
- Xử lý SQLException hợp lý.
- Đảm bảo DAO method trả đúng kiểu dữ liệu contract.
- Không gọi Service.
- Không gọi UI.

Bàn giao cho BLL:
- Method DAO chạy được.
- Input/output đúng contract.
- Query đúng dữ liệu.
- Không làm sai foreign key.
- Có test thủ công hoặc dữ liệu mẫu để kiểm tra.

---

## 3.2. Người làm BLL/Service

Phụ trách:
- AuthService
- UserService
- CategoryService
- RecruitmentService
- ApplicationService
- CVService
- NotificationService nếu làm sau
- Session/Validation/ID generator nếu cần

Nhiệm vụ chính:
- Gọi DAO.
- Xử lý nghiệp vụ.
- Validate dữ liệu.
- Kiểm tra role/session.
- Sinh ID đúng format.
- Mapping Model sang DTO nếu cần.
- Trả kết quả cho View.

Bàn giao cho View:
- Service method dùng được.
- Input/output rõ ràng.
- Trả DTO đủ field.
- Trả boolean/null/List rỗng nhất quán.
- Không throw lỗi khó hiểu lên View nếu không cần.

---

## 3.3. Người làm View/Swing

Phụ trách:
- LoginPanel
- RegisterPanel
- JobSearchPanel
- JobDetailPanel
- AppliedJobsPanel
- CVEditorPanel
- Employer panels
- Admin panels
- HeaderPanel
- SidebarPanel
- MainFrame navigation

Nhiệm vụ chính:
- Hiển thị giao diện.
- Lấy input người dùng.
- Gọi Service.
- Render DTO lên UI.
- Hiển thị thông báo lỗi/thành công.
- Dùng mock DTO khi Service chưa hoàn thiện.
- Không gọi DAO.

Bàn giao:
- UI gọi đúng Service method.
- Render đúng DTO field.
- Không lỗi giao diện cơ bản.
- Có xử lý empty state/error state.
- Không viết SQL trong View.

---

## 4. Mức độ nặng của từng phần

1. DAL/DAO - nặng nhất
Lý do:
- Phải viết SQL đúng.
- Phải join nhiều bảng.
- Phải mapping ResultSet.
- Dễ lỗi FK, enum, date/time.
- Là nền cho BLL.

2. BLL/Service - nặng nhì
Lý do:
- Phải xử lý nghiệp vụ.
- Phải kiểm tra quyền/session.
- Phải gọi nhiều DAO đúng thứ tự.
- Phải đảm bảo dữ liệu trả cho View đúng.

3. View/Swing - nặng ba
Lý do:
- Nhiều file và tốn công UI.
- Nhưng có thể làm bằng mock DTO trước.
- Ít rủi ro dữ liệu hơn nếu contract rõ.

Lưu ý:
Nếu UI hiện tại chưa hoàn thiện, phần View có thể tốn thời gian nhiều nhất về chỉnh giao diện, nhưng về rủi ro logic thì DAL vẫn nặng nhất.

## 6. Thứ tự module ưu tiên

DAO cần:

Done khi:

## 8. Checklist trước khi code một chức năng

Trước khi code, trả lời đủ:

1. Màn hình nào dùng chức năng này?
2. View gọi Service method nào?
3. Input của Service là gì?
4. Output của Service là gì?
5. DTO cần field nào?
6. Service gọi DAO nào?
7. DAO query bảng nào?
8. Có cần JOIN không?
9. Có cần check role/session không?
10. Có cần validate không?
11. Có ảnh hưởng schema không?
12. Có ảnh hưởng DTO đang dùng ở View khác không?

Nếu chưa trả lời đủ, chưa nên code.

## 9. Checklist bàn giao DAL

Một DAO method chỉ xem là xong khi:

- SQL chạy được.
- Mapping đúng field.
- Không lỗi null cơ bản.
- Có xử lý SQLException.
- Không gọi Service/View.
- Trả đúng kiểu contract.
- Có test bằng dữ liệu mẫu.
- Compile thành công.

---

## 10. Checklist bàn giao BLL

Một Service method chỉ xem là xong khi:

- Gọi đúng DAO.
- Validate dữ liệu cần thiết.
- Check role/session nếu cần.
- Xử lý case null/empty.
- Trả kết quả đúng contract.
- Không có code Swing.
- Không có SQL trực tiếp.
- Compile thành công.

---

## 11. Checklist bàn giao View

Một màn hình chỉ xem là xong khi:

- Gọi đúng Service.
- Lấy input đúng.
- Render DTO đúng.
- Có xử lý danh sách rỗng.
- Có thông báo lỗi/thành công.
- Không gọi DAO.
- Không viết SQL.
- Không phụ thuộc dữ liệu mock khi tích hợp thật.
- Compile thành công.

## 13. Quy tắc tránh xung đột

1. Không sửa file người khác đang làm nếu chưa báo.
2. Không đổi DTO tùy tiện.
3. Không đổi Service signature tùy tiện.
4. Không sửa schema tùy tiện sau khi DAO đã code.
5. Nếu cần đổi contract, báo cả 3 người.
6. Mỗi ngày nên merge/check compile ít nhất một lần.
7. Sau khi pull code, chạy compile trước khi code tiếp.

## 14. Rủi ro cần kiểm soát

Rủi ro 1:
DTO thiếu field View cần.

Cách xử lý:
Chốt contract trước khi code View.

Rủi ro 2:
DAO query sai schema.

Cách xử lý:
Bám schema.sql, test SQL riêng trước.

Rủi ro 3:
Service bị biến thành nơi viết SQL.

Cách xử lý:
Mọi SQL phải nằm trong DAO.

Rủi ro 4:
View gọi DAO cho nhanh.

Cách xử lý:
Cấm View gọi DAO. View chỉ gọi Service.

Rủi ro 5:
ID sinh ra vượt VARCHAR(10).

Cách xử lý:
Dùng format đã chốt:
- U-00000001
- EMP-000001
- CAN-000001
- REC-000001
- APP-000001
- CV-0000001
- CAT-000001
- NOT-000001
- EDU-000001
- WE-0000001
- CERT-00001
