PHẦN 1: TỔNG QUAN HỆ THỐNG
================================================================

1.1. HỆ THỐNG LÀM GÌ
--------------------------------
JobPortalSystem là ứng dụng desktop Java (Swing) hỗ trợ kết nối
nhà tuyển dụng và ứng viên. Hệ thống cho phép:
- Ứng viên tìm kiếm, xem chi tiết và ứng tuyển vào các vị trí
  tuyển dụng, đồng thời quản lý CV cá nhân.
- Nhà tuyển dụng đăng tin, quản lý tin đăng và xét duyệt hồ sơ
  ứng viên.
- Admin kiểm duyệt tin đăng, quản lý người dùng, danh mục và
  xem thống kê hệ thống.

1.2. CÁC ACTOR/ROLE
--------------------------------
- CANDIDATE  (Ứng viên)       : Tìm việc, ứng tuyển, quản lý CV
- EMPLOYER   (Nhà tuyển dụng) : Đăng tin, duyệt hồ sơ, quản lý
                                  thông tin công ty
- ADMIN      (Quản trị)       : Kiểm duyệt tin, quản lý người
                                  dùng, danh mục, xem thống kê

1.3. CÁC MODULE CHÍNH
--------------------------------
M1. Auth         : Đăng ký, đăng nhập, đổi mật khẩu
M2. Recruitment  : Đăng/sửa/xóa/duyệt tin tuyển dụng
M3. Application  : Ứng tuyển, hủy, duyệt/từ chối hồ sơ
M4. CV           : Quản lý CV (objective, skills, education)
M5. Category     : Quản lý danh mục ngành nghề
M6. User         : Cập nhật thông tin cá nhân / công ty
M7. Notification : Xem thông báo, đánh dấu đã đọc
M8. Admin Stats  : Thống kê hệ thống (chỉ đọc)

MH-01: Đăng nhập (LoginPanel)
------------------------------------------------------------
Role sử dụng  : Tất cả (CANDIDATE, EMPLOYER, ADMIN)
Mục đích      : Xác thực người dùng, điều hướng đến dashboard
                tương ứng với role.
Dữ liệu hiện thị:
  - Logo JobPortal
  - Tab chọn role: Candidate / Employer / Admin
Dữ liệu nhập :
  - username (JTextField)
  - password (JPasswordField)
  - role     (tab selection → ánh xạ sang enum Role)
Hành động/Nút bấm:
  - [Login]            → gọi AuthService.login()
  - [Forgot password?] → ĐỀ XUẤT BỎ QUA (không có trong Use Case,
                         không có restorePsw trong DB hiện tại)
  - [Create an account]→ chuyển sang RegisterPanel
Ghi chú:
  - UI có nút "Sign up with Google" → LOẠI BỎ, không có trong
    Use Case và không khả thi trong desktop app.
  - Role được chọn từ tab, truyền vào login() để verify khớp
    với role thực trong DB.

File view   : view/common/LoginPanel.java
Service     : AuthService.login()
DAO         : UserDAO.findByUsernameAndPassword()
DTO         : UserDTO
Model       : User

MH-06: Quản lý CV (CVEditorPanel)
------------------------------------------------------------
Role sử dụng  : CANDIDATE
Mục đích      : Tạo và chỉnh sửa CV cá nhân.
Dữ liệu hiển thị:
  - Thông tin cá nhân: fullName, email, phoneNumber
    (lấy từ User, chỉ đọc tại đây)
  - Objective (JTextArea)
  - Skills: danh sách tag, ô nhập thêm
  - Education History: bảng school, major, year, actions
Dữ liệu nhập :
  - objective   (JTextArea)
  - skill       (JTextField + nút ADD)
  - education   (dialog: school, degree, major, startYear, endYear)
                 → BỎ trường description theo ghi chú nhóm
Hành động/Nút bấm:
  - [Add Skill]       → CVService.addSkill()
  - [x] trên tag      → CVService.removeSkill()
  - [Add Education]   → mở dialog → CVService.addEducation()
  - [✏️] Education    → mở dialog điền sẵn → CVService.updateEducation()
  - [🗑️] Education    → CVService.removeEducation()
  - [Save Profile]    → CVService.saveCV() ← lưu TOÀN BỘ một lần
  - [Discard Changes] → LOẠI BỎ theo ghi chú nhóm
Ghi chú:
  - Thao tác add/remove skill/edu chỉ thay đổi state trong memory,
    CHƯA lưu DB. Chỉ khi bấm [Save Profile] mới gọi saveCV().
  - Không có WorkExperience và Certification trong UI hiện tại
    → ĐỀ XUẤT BỔ SUNG sau nếu còn thời gian.

PHẦN 6: PHÂN TÍCH THIẾU/SAI/LỆCH

6.1. HÀM CÒN THIẾU TRONG DANH SÁCH BAN ĐẦU
--------------------------------------------
- ApplicationService.hasApplied()        → cần cho JobDetailPanel
- ApplicationService.getNewApplicantsToday() → cần cho EmployerDashboard
- RecruitmentService.closeRecruitment()  → Use Case có "Đóng tin"
- RecruitmentService.countOpenRecruitments() → cần cho AdminDashboard
- RecruitmentService.getTopEmployers()   → cần cho AdminDashboard
- UserService.getEmployerInfo()          → cần load form CompanyInfo
- UserService.deleteUser()               → cần cho UserManagement
- NotificationService.sendNotification() → bị thiếu hoàn toàn
- CategoryService.updateCategory()       → bị thiếu trong danh sách ban đầu

6.2. USE CASE CHƯA CÓ UI / CẦN LƯU Ý
--------------------------------------
- "Xem thông báo": Use Case có, nhưng không có màn hình riêng.
  → ĐỀ XUẤT: Hiện popup/list khi click icon chuông trong HeaderPanel.
- "Đổi mật khẩu": Có trong hàm ban đầu nhưng không có màn hình.
  → ĐỀ XUẤT: Thêm tab trong My Account nếu còn thời gian.

6.3. UI LỆCH SO VỚI USE CASE / CLASS DIAGRAM
---------------------------------------------
- RegisterPanel thiếu trường chọn ROLE (Ứng viên / Nhà tuyển dụng)
  → Cần thêm JComboBox.
- RecruitmentFormPanel có "Lưu nháp" nhưng không có trong Use Case
  và không có trường isDraft trong Model → LOẠI BỎ.
- JobDetailPanel có "Add to Bookmarks" và "Share Job" → LOẠI BỎ.
- AppliedJobsPanel có "Export" → LOẠI BỎ.
- ApplicationReviewPanel có "Gợi ý AI", "Nâng cấp tin" → LOẠI BỎ.
- CompanyInfoPanel hiện thị "Trạng thái hồ sơ %" → LOẠI BỎ.
- EmployerDashboardPanel có "Gói dịch vụ / Gia hạn" → LOẠI BỎ.
- AdminDashboardPanel "tỷ lệ phản hồi" không có dữ liệu trực tiếp
  → Tính thủ công hoặc hiển thị N/A.

6.4. HÀM NÊN ĐẶT Ở SERVICE THAY VÌ VIEW
-----------------------------------------
- Logic kiểm tra "đã apply chưa" phải ở ApplicationService,
  không để trong JobDetailPanel tự query.
- Logic validate form (email, password...) phải qua ValidationUtils,
  không viết thẳng trong panel.
- Logic phân trang (offset/limit) nên tính trong Service hoặc DAO,
  không tính trong View.

6.5. HÀM NÊN ĐẶT Ở DAO
------------------------
- Mọi câu SQL (SELECT, INSERT, UPDATE, DELETE) phải ở DAO.
- Không viết SQL trực tiếp trong Service hay Panel.

6.6. LOGIC BỊ TRÙNG CÓ THỂ XẢY RA
------------------------------------
- Lấy employer từ session: dùng chung 1 helper trong SessionManager
  thay vì mỗi Service tự query lại EmployerDAO.
- Gửi thông báo sau approve/reject/moderate: gom vào 1 hàm helper
  private trong từng Service, không viết lặp.
